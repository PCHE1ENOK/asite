## Визуальное направление

Рабочее имя темы — **Ai** (藍, японское индиго). Тёмная тема — основная: аниме смотрят вечером, постеры ярче на тёмном. Нейтрали слегка уходят в индиго, акцент — один, индиго-синий. Цвет в интерфейсе несут постеры; хром остаётся тихим. Заголовки набраны широким Unbounded, интерфейс — Golos Text.

## Журнал решений

**2026-10-29 — проход 1**

1. **Темы.** Две темы через токены, тёмная по умолчанию, переключатель «Системная / Тёмная / Светлая». Flutter: `ColorScheme` для стандартных виджетов + `ThemeExtension<AppTokens>` для своих токенов (`surface1..3`, `fg2/fg3`, `accentSoft`, статусы, `good/warn/bad`).
2. **Контраст.** Проверено скриптом (WCAG 2.x): все пары текст/поверхность ≥ 4.5:1 в обеих темах. Самые близкие к порогу: `fg3` на `surface2` — 4.85 (тёмная) и 4.50 (светлая); `good` на `surface2` в светлой — 5.20. Белый текст плеера на скриме 70% ≥ 8:1 даже на белом кадре. `onAccent` на `accent` — 7.2 (тёмная) / 6.7 (светлая).
3. **Цвета статусов списка** (`CURRENT`, `PLANNING`, `COMPLETED`, `PAUSED`, `DROPPED`) взяты из проверенной категориальной палитры в этом порядке; валидатор dataviz: худшая соседняя пара для дальтоников ΔE 9.1 (светлая) / 8.4 (тёмная), всё PASS. В светлой теме у трёх цветов контраст с фоном < 3:1, поэтому статус **всегда с иконкой и подписью**, а составная полоса — с легендой и числами.
4. **Рейтинг AniList** (`averageScore`) — целое число в бейдже: ≥ 75 зелёный, 60–74 жёлтый, < 60 красный, нет оценки — «—». На постере бейдж всегда на тёмной подложке, чтобы читаться на любой обложке.
5. **Шрифты:** Unbounded (заголовки, название тайтла, крупные числа) + Golos Text (всё остальное). Оба OFL с кириллицей, бандлим в ассеты, не тянем из сети. Цифры таблично (`FontFeature.tabularFigures()`).
6. **Сетка.** Брейкпоинты 640 / 1008 / 1440 (как у Fluent). NavRail 72, развёрнутый 248 от 1440; на телефоне — нижний таб-бар. Постер 2:3, ширина 148–220, `SliverGridDelegateWithMaxCrossAxisExtent`. Шкала отступов 4-pt. Радиусы: 4 / 6 / 10 / 16 / 24 / pill.
7. **Состояния.** Hover — слой `fg` 6%, pressed — 12%, selected — `accentSoft`, focus — кольцо 2px `accent` (только с клавиатуры), disabled — 38%. Загрузка — скелетоны той же геометрии. Пусто и ошибка — одна фраза + одно действие, уже загруженное не прячем.
8. **Плеер.** Оверлей прячется через 3 с. Серия «просмотрена» на 85% или со стартом эндинга → локальный прогресс (SQLite) + тост с «Отменить». Синхронизация — через приватный GitHub Gist (п. 13). Первая серия без статуса ставит «Смотрю», последняя — «Просмотрено» и диалог оценки. Карточка следующей серии за 20 с до конца, отсчёт 10 с, Esc — отмена. Выбор озвучки запоминается на тайтл, смена сохраняет позицию.

**2026-10-29 — проход 1, поправки после ответа кодинг-чата**

9. **Статусы локальные.** Списки и автостатусы работают по локальной базе без входа в AniList. Синхронизация с AniList — позже, необязательная; значки «ожидает синхронизации» появятся только вместе с ней.
10. **Источник видео абстрактный.** В интерфейсе нет названий сайтов. `DubPicker` рассчитан на 1–10+ вариантов: до 4 — сегменты на карточке, от 7 — группы и фильтр в поповере, один вариант — без списка.

**2026-10-29 — решения пользователя (через головной чат)**

11. **Платформы:** Windows, iOS и Android. Mica только на Windows 11, на остальных сплошной фон. На Android нижний `NavigationBar` Material 3, зона нажатия 48.
12. **Иконки:** Material Symbols Rounded на всех платформах (`material_symbols_icons`).
13. **Вход через GitHub, списки в приватном Gist.** Экран входа по Device Flow (код + github.com/login/device), вход не обязателен. Состояния синхронизации: синхронизировано / не синхронизировано / идёт / ошибка сети / не вошёл — точка на профиле и полоса над «Моими списками». Пункт 9 уточнён: локальная база остаётся источником на устройстве, AniList для записи статусов не используется.
14. **18+** показывается сразу с бейджем «18+» (`Media.isAdult`), без размытия и подтверждения возраста. Фильтр «Показывать 18+» в каталоге, по умолчанию включён.

**2026-10-29 — подтверждено пользователем**

15. **Объединение при входе** автоматическое, без диалога: по каждому тайтлу остаётся более свежая запись, тайтлы только с одной стороны сохраняются. Итог — строкой на экране «Готово».
16. **Экран входа** показывается один раз при первом запуске, его можно пропустить. Дальше вход — только по желанию пользователя (пункт «Войти», кнопка в `SyncBar`).

**2026-10-29 — поиск и настройки (задание пользователя)**

17. **Поиск** — отдельный экран: поле с фокусом, недавние и популярные запросы, подсказки с подсветкой, результаты сеткой каталога; пусто и ошибка сети. Запрос через 300 мс от 2 символов. Ctrl+K открывает поиск с любого экрана.
18. **Настройки:** аккаунт GitHub со статусом синхронизации и входом/выходом, «Показывать 18+» (вкл., с бейджем, одно значение с фильтром каталога), тема (системная по умолчанию), язык, версия. На телефоне настройки открываются вкладкой «Профиль». Платформенные контролы — в таблице screens.md §7.
19. **Диалог оценки** в первом проходе не делаем (решение пользователя).
20. **Скриншоты** экранов лежат в `design/screenshots/`, снимаются из прототипа в Chromium.

**2026-10-29 — iOS и Android в нативных контролах (задание головного чата)**

21. **Граница общего и платформенного.** Шрифты, цвета, постеры, бейджи, статусы и логика экранов общие. Платформе отдаются навигация, заголовки, переключатели, сегменты, шиты, поиск, вид списка настроек и жесты.
22. **iOS:** `CupertinoTabBar` с blur, large title, «‹ Назад» текстом, `CupertinoSwitch`, sliding segmented control, action sheet для статуса и языка, inset grouped настройки.
23. **Android:** `NavigationBar` M3 с индикатором-пилюлей, large top app bar, `Switch` и `SegmentedButton` M3, filter chips с галочкой, bottom sheet с радио, плоский список настроек с заголовками `accent`, кнопки-пилюли.
24. **Плеер на телефоне** — только альбомная ориентация, три кнопки по центру, двойной тап ∓10 с, PiP при уходе в фон.
25. **Английский перевод** не начинаем (решение пользователя).

**2026-10-29 — полный экран в плеере (замечание пользователя)**

26. **Кнопка «Полный экран» работает на всех платформах** как режим приложения: скрываются заголовок окна и NavRail (Windows), строка состояния и навигация (Android, immersive sticky), строка состояния (iOS, без системного плеера AVKit). Остаются видео и управление. Выход — повторное нажатие или Esc, клавиша F переключает. **Для кодинга:** флаг `isFullscreen` в состоянии плеера + `SystemChrome.setEnabledSystemUIMode(immersiveSticky / edgeToEdge)`, на Windows `window_manager.setFullScreen`; браузерный Fullscreen API в прототипе не используется.

**2026-10-29 — браузеры пользователя**

27. **Прототип смотрится в Firefox (Windows), Yandex Browser на iOS (WebKit) и Yandex Browser на Android (Chromium).** По итогам проверки исправлено:
    - горячие клавиши (F, S, Shift+N, Ctrl+K, пробел) не работали при русской раскладке: `e.key` давал «а», «ы», «т», «л». Теперь проверяется `e.code` (физическая клавиша). **Для кодинга:** в Flutter `Shortcuts` то же самое — `LogicalKeyboardKey` зависит от раскладки, для F/S/N/K нужен `PhysicalKeyboardKey` или `SingleActivator` по физической клавише;
    - на телефоне строка демо-переключателей прототипа была шире 390 px, и браузер уменьшал всю страницу. Теперь она прокручивается внутри себя;
    - высота приложения `100dvh` — нижняя навигация стоит над нижней панелью Яндекса, а не под ней;
    - hover-эффекты постеров только при `(hover: hover)` — на iOS тап не оставляет «залипшее» наведение;
    - поля и списки на сенсорных экранах 16px — WebKit не увеличивает страницу при фокусе;
    - поле поиска без нативного оформления WebKit (`appearance: none`);
    - запасные цвета под `@supports not (color-mix…)` для Safari < 16.2 и Firefox < 113;
    - платформа в прототипе по умолчанию выбирается по устройству: iPhone/iPad → iOS, Android → Android, остальное → Windows.

**2026-10-29 — распознавание музыки (этап 4.5, AcoustID)**

28. **«Что играет»** — иконка ноты в верхней панели плеера, результат в поповере: распознаётся / найдено (название, исполнитель, обложка, «Открыть в MusicBrainz», «Скопировать») / не найдено / ошибка сети / выключено. Видео при распознавании не останавливается, оверлей не прячется, пока поповер открыт.
29. **Настройка «Распознавать музыку»** в новой группе «Плеер», по умолчанию выключена, с текстом про отправку фрагмента на AcoustID. Из выключенного состояния в плеере можно включить одной кнопкой «Включить и распознать» — текст о приватности показан рядом с ней. **Для кодинга:** флаг в настройках `musicRecognition=false`; состояния панели `off | listening | found | notfound | error`; внешняя ссылка — на запись MusicBrainz по recording MBID из ответа AcoustID.

**2026-10-29 — профили (просьба пользователя)**

30. **Профили на одном устройстве.** У профиля свои списки, прогресс, «Продолжить», недавние запросы, вход в GitHub, Gist и синхронизация. Общие: «Показывать 18+» (решение пользователя), тема, язык, распознавание музыки.
31. **Где переключатель — решение дизайна.** Windows: аватар профиля внизу NavRail открывает меню профилей. Он виден на всех экранах, а шапка каталога есть только в каталоге — поэтому не в шапке каталога. iOS/Android: вкладка «Профиль» → Настройки, первая группа «Профили»; долгое нажатие на вкладку — быстрый выбор.
32. **Один аккаунт GitHub — один профиль.** Повторная привязка блокируется сообщением «Этот аккаунт уже привязан к профилю «…»» с выходами «Войти другим аккаунтом» / «Переключиться на «…»».
33. **Удаление профиля** только с подтверждением: локальные списки удаляются, Gist на GitHub не трогается. Текущий и последний профиль удалить нельзя. **Для кодинга:** таблица `profiles(id, name, color, githubLogin UNIQUE NULL)`, все пользовательские таблицы с `profileId`; настройки устройства — отдельно от профиля.

**2026-10-29 — плеер на реальных данных**

34. **Модель плеера**: серия (номер, название или «Серия N», длительность, дата выхода), озвучка (студия, тип, язык, качество, доступность), сезон (из связей AniList SEQUEL/PREQUEL), интервалы опенинга/эндинга, следующая серия. Недоступная озвучка видна, но серая и не выбирается.
35. **Панель «Серии» в плеере** с сезонами; не вышедшие серии видны с датой, но не открываются.
36. **Состояния**: загрузка серии, буферизация, «Видео недоступно» (с выбором другой озвучки и повтором, позиция сохраняется), «Источники видео не подключены» (с ручной отметкой серии), полный экран. **Для кодинга:** «Начать просмотр» сейчас ведёт в состояние «Источники не подключены» — это задуманный экран, а не заглушка; ручная отметка серии идёт тем же путём, что автоотметка на 85% (тост «Отменить», автостатусы).

**2026-10-30 — верхняя панель прототипа на телефоне (замечание пользователя, iPhone + Yandex Browser)**

37. **Панель демо-переключателей прототипа на телефоне свёрнута в одну кнопку.** Подпись «Ai» заменена на «Anilist» и на телефоне скрыта. В строке остаются «Прототип · примерные данные» и «Демо-настройки ▾»; по нажатию переключатели раскрываются сеткой 2×2 с подписями (Данные, Синхронизация, Плеер, Платформа) и кнопкой «Тема», ничего не обрезается и не уезжает за экран. Ряд фильтров каталога прокручивается по горизонтали с затуханием правого края, чтобы было видно, что он продолжается. Проверено на 390 px (эмуляция iPhone с UA Yandex Browser, Chromium): ширина страницы = ширина экрана, ни один элемент шапки не выходит за край. Скриншоты 80–81. К приложению это не относится — это панель прототипа, в настоящем приложении её нет.

38. **Телефон в альбомной ориентации** (замечание пользователя). Раньше экран 844×390 считался «десктопом»: панель демо-настроек шла в одну длинную строку и обрезалась, а прототип рисовал уменьшенную рамку телефона, которая не помещалась. Теперь:
    - низкий экран (высота ≤ 500 px) считается телефоном в любой ориентации: панель свёрнута в «Демо-настройки ▾», раскрывается в одну строку из четырёх списков и «Тема»;
    - рамка телефона показывается только там, где экран просторнее самого телефона (ширина > 640 и высота ≥ 600, то есть ПК и планшет). На настоящем телефоне прототип идёт без рамки, на весь экран, с нижней навигацией платформы;
    - проверено на 844×390 (iPhone, UA Yandex Browser) и 932×430 (Android, UA Yandex Browser) в эмуляции Chromium: ширина страницы = ширина экрана, ни один элемент не выходит за край, нижняя навигация целиком видна (низ = низ экрана), плеер на весь экран. Скриншоты 82–87.

**2026-10-30 — плеер под официальное видео YouTube (этап 6, по коду рабочего чата)**

39. **Встроенный плеер YouTube не перекрываем.** Наши панели — над и под видео, не поверх (правила YouTube API). Отсюда другая раскладка, чем у плеера §4/§10: верх (назад, название, «Серии», полный экран), сцена 16:9, низ (источник, «Просмотрено», следующая серия).
40. **Что скрыто в режиме YouTube:** выбор озвучки, «Пропустить опенинг», «Что играет», наш таймлайн и центральные кнопки. Субтитры и качество — внутри плеера YouTube; его собственный полный экран выключен (`fs=0`), используем наш.
41. **Состояния YouTube:** воспроизведение, ролик закончился (следующая серия в нижней панели, не поверх видео), нет видео для серии (отметка «нет видео» в панели «Серии» + ручная отметка), недоступно в регионе / встраивание запрещено (101/150), удалено (100), без встроенного плеера (открыть в браузере + ручная отметка). **Для кодинга:** прогресс и автоотметка 85% — через IFrame API (`getCurrentTime`, `ENDED`); коды ошибок плеера → карточки из screens.md §11.

**2026-10-30 — аудит кнопок плеера (замечание пользователя)**

42. **Все кнопки плеера проверены скриптом** на 1440×900, 390×844 и 844×390 (150 прогонов, все прошли), таблица — `player-audit.md`, сам скрипт — `prototype/player-audit.test.js`. ## Проверки

- Контраст токенов: скрипт WCAG, результаты выше.
- Палитра статусов: `validate_palette.js` из навыка dataviz, обе темы.
- Новые элементы: ручка выключенного переключателя к треку 6.2:1 (тёмная) / 6.4:1 (светлая), текст на подсветке совпадения 7.9:1 / 10.2:1, белый на бейдже 18+ 5.9:1. Рамка трека сама по себе 1.7:1 — состояние несут ручка и заливка, этого достаточно.
- Мобильные контролы: ручка выключенного переключателя Android к треку 6.2 / 6.4 (те же токены `fg2`/`surface3`), iOS — белая ручка на сером треке с тенью, как в системе. Текст опций в шитах — `accent` и `fg` на `surface1/2`, ≥ 5.6:1.
- Прототип: рендер в Chromium на 1300–1400 и 400 px, включая вход и состояния синхронизации, обе темы, без горизонтального скролла и ошибок JS.
